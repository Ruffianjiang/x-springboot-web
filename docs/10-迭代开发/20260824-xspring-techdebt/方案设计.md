## 2. 技术债 1：configLoader 警告

### 2.1 现状
- 三个文件均为 ESM（`import`/`export`）。
- `mock/index.js` 为 CJS（`require('mockjs')` + `module.exports`），由 `vite/plugins/mock.js` 通过 `createRequire(import.meta.url)` 加载——**与文件是否被当作 ESM 无关**，createRequire 始终按 CJS 解析。
- Vite 8 计划将 `configLoader: 'native'` 设为默认（原生按文件扩展名判定 ESM/CJS）。当前这三个 `.js` 因最近的 package.json 未声明 `"type":"module"` 而被当作 CJS，但内部是 ESM 语法 → 触发警告。

### 2.2 方案对比

| 方案 | 改动 | 优点 | 风险 / 代价 |
|------|------|------|------------|
| **A. 三个文件改名 `.mjs`** | `vite.config.js`→`vite.config.mjs`；`svg-icons.js`→`svg-icons.mjs`；`mock.js`→`mock.mjs`；`vite.config.js` 内 `import './vite/plugins/svg-icons.js'` 等路径同步改 `.mjs` | 局部、精准；不动 package.json，不波及任何 CJS 文件；Vite 原生识别 `.mjs` 为 ESM，警告消除 | 改动 3 文件名 + 2 处 import 路径；CI/构建需重新验证 |
| **B. package.json 加 `"type":"module"`** | 改 1 行 | 一次性消除所有 `.js` 的 ESM/CJS 歧义 | **副作用大**：`mock/index.js` 变 ESM 后 `require`/`module.exports` 失效；`mock/user.js`、`mock/table.js`、`mock/utils.js` 同为 CJS 需全改 ESM；`postcss.config.js`/`babel.config.js`（若存在）也可能受影响。需全盘排查 CJS 文件 |

### 2.3 推荐决策（待确认）
**推荐方案 A（改名 `.mjs`）**：影响面最小、精准消除警告，不触碰 CJS 模块。`mock/index.js` 维持 CJS 不变（createRequire 照常工作）。

> 决策点 D1：是否采纳方案 A（改名 `.mjs`）？还是选 B（type:module，需连带迁移全部 CJS mock 模块）？

## 3. 技术债 2：Sass `@import` → `@use` / `@forward`

### 3.1 现状（7 处）
- `src/styles/index.scss`：5 处 `@import './variables.scss';` 等（聚合入口）。
- `src/layout/index.vue`：2 处 `@import "@/styles/mixin.scss";` 与 `@import "@/styles/variables.scss";`（SFC `<style>` 内）。

被引用文件：`variables.scss`、`mixin.scss`、`transition.scss`、`element-ui.scss`、`sidebar.scss`（均在 `src/styles/`）。

### 3.2 迁移规则
- `@import` → `@use`：成员需通过命名空间访问（`@use 'variables' as *;` 可保持无前缀调用，等价于原 `@import` 全局注入）。
- Dart Sass 要求 `@use` 必须位于文件最前（不能像 `@import` 可放任意位置）。`src/layout/index.vue` 的两处 `@import` 位于 `<style>` 内、其它样式规则之后，**必须上移到 `<style>` 首行**。
- `@use` 同名文件只加载一次（天然去重），无副作用。
- `@forward` 仅在需"转发"多个模块时使用；本场景是"使用"，用 `@use` 即可，`index.scss` 作为聚合入口可保留 `@use` 逐条引入（或改为 `@forward` 供外部 `@use`，但当前是 `@import index.scss` 整体，保持 `@use` 即可）。

### 3.3 改动清单
1. `src/styles/index.scss`：5 处 `@import './X.scss';` → `@use './X.scss';`（X = variables/mixin/transition/element-ui/sidebar）。无需 `as *`（同目录相对引入，`@use` 默认命名空间为文件名，若内部仅变量/混入且调用无前缀则需 `as *`——见下方注意）。
2. `src/layout/index.vue`：`<style>` 内两处 `@import` 上移至首行，改为 `@use '@/styles/mixin.scss' as *;` 与 `@use '@/styles/variables.scss' as *;`（用 `as *` 保持原有无前缀变量/混入调用，避免大规模改调用点）。

> **注意（关键）**：原 `@import` 将 variables/mixin 的 `$变量`/`@mixin` 注入全局作用域，SFC 与其它 scss 直接无前缀调用。`@use` 默认带命名空间（如 `variables.$x`），会破坏现有调用。**因此统一加 `as *` 还原全局可见性**，是改动最小、回归风险最低的方案。需逐一确认 variables/mixin 的调用点是否依赖全局注入——本模板中 `variables.scss` 定义 `$` 变量、`mixin.scss` 定义 `@mixin`，被 `index.scss` 及各 SFC 引用，加 `as *` 可全覆盖。

### 3.4 验证
- `npm run build:prod` 通过（Sass 编译无错、无弃用警告）。
- 同进程 dev 验证（`vite.createServer` + fetch）：`/` 与 `/src/main.js` 正常，样式模块编译无误。

> 决策点 D2：Sass 迁移采用 `@use ... as *`（最小改动、保持全局可见）是否可接受？还是要求规范化为显式命名空间（改动大、需逐调用点改前缀）？

## 3.5 实施记录（2026-08-24，已实施）

**决策确认**：D1=A（改名 `.mjs`）、D2=`@use ... as *`。

**实际改动清单**
- 技术债 1（configLoader）：
  - 新增 `vite.config.mjs`、`vite/plugins/svg-icons.mjs`、`vite/plugins/mock.mjs`（内容同原 `.js`，扩展名改 `.mjs`）。
  - 删除 `vite.config.js`、`vite/plugins/svg-icons.js`、`vite/plugins/mock.js`。
  - **连带项**：`vitest.config.js` 也 import 了 `svg-icons.js`，一并改名 `vitest.config.mjs` 并删原文件（否则 vitest 启动报 `UNRESOLVED_IMPORT`）。`mock/index.js` 维持 CJS 不变（`createRequire` 照常加载）。
- 技术债 2（Sass `@import`→`@use`）：
  - `src/styles/index.scss`：5 处 `@import`→`@use ... as *`。
  - `src/layout/index.vue`：`<style>` 内 2 处 `@import`→`@use ... as *`（上移至 `<style>` 首行）。
  - **修复一处 `@use` 作用域回归**：`src/styles/sidebar.scss` 内部使用 `$sideBarWidth`/`$menuBg`（定义在 `variables.scss`），原靠 `index.scss` 的 `@import` 全局注入；`@use` 不继承该注入，故在 `sidebar.scss` 顶部补 `@use 'variables.scss' as *`。`element-ui.scss`/`transition.scss`/`mixin.scss` 经核查不引用变量/混入，无需补。

**验证结果（全绿）**
- `npm run lint`：0 error / 2 warning（与 Stage 3 一致的 vue-admin 既有风格，非本次引入）。
- `npm run test`：28/28 通过（vitest）。
- `npm run build:prod`：✓ built in 9.56s，**configLoader 警告与 Sass `@import` 弃用警告均消除**（仅剩 chunk 体积提示，与本次无关）。
- 同进程 dev 验证（Vite 8.2.2）：`/` 200（含 `#app`/`/src/main.js`）、`/src/main.js` 含 `createApp`、`/dev-api/.../table/list` 与 `user/info` 返回 `code:20000`，**无任何 configLoader/Sass 警告输出**。

**与方案偏离点**：方案未预见到 `vitest.config.js` 也引用被改名的插件，以及 `sidebar.scss` 对 `variables.scss` 的隐式依赖；实施中均已修复并记录。

## 5. 风险

- 技术债 1 方案 B 波及 CJS mock 模块，回归面大；优先 A。
- 技术债 2 的 `as *` 若与现有命名空间冲突（极少见）会报错，需 build 验证暴露。
- `@use` 顺序敏感（必须文件最前），`layout/index.vue` 上移若遗漏会导致编译失败——属可立即发现、可立即修的硬错误。
