## 1. 背景与目标

1. **Stage 1 只解决"可编译"，Stage 2 解决"可运行"**：Stage 1 建立了 Vite 8 构建管道与 Vue3 启动骨架，`vite build` 通过，但 views/layout 仍残留 **Vue 2 模板/运行时语法**，在 Vue 3 下直接报错（模板编译期或运行期）；同时 element-ui 字体图标在依赖移除后不再渲染；`el-submenu` 在 element-plus 中已改名 `el-sub-menu`。
2. **目标**：让应用在 dev 与生产构建下**真正跑起来**，且视觉/交互与原 element-ui 版对齐；**不引入任何新依赖**（element-plus 2.14.4 + @element-plus/icons-vue 2.3.2 已于 Stage 1 装入）。
3. 范围严格限定为"使运行时成立 + 图标正确"，**不扩展功能**；element-plus 组件级 API 行为差异靠 dev 人工走查兜底（无自动化基线）。

## 3. 迁移方案

### 3.1 分支策略

- 新分支 **`fix/migrate-vue3-stage2`** 自 `master`（`03bdadea`）切出。Stage 1 PR 已合并，不复用旧分支以避免历史混淆。
- 单 PR 提交（squash），合并由你 review，不自动合并。
- [决策点 D1] 新分支 vs 复用 `fix/migrate-vue3-vite` —— **建议新分支**。

### 3.2 Vue2 模板语法修复（阻断运行时，必须改）

| 文件:行 | 现状（Vue2） | 目标（Vue3） |
|---------|-------------|-------------|
| `Navbar.vue:13` | `<el-dropdown-menu slot="dropdown">` | `<el-dropdown-menu #dropdown>`（或 `<template #dropdown>` 包住子项） |
| `SidebarItem.vue:12` | `<template slot="title">` | `<template #title>` |
| `login/index.vue:37` | `@keyup.enter.native="handleLogin"` | `@keyup.enter="handleLogin"` |
| `login/index.vue:44` | `@click.native.prevent="handleLogin"` | `@click.prevent="handleLogin"` |
| `Navbar.vue:25` | `@click.native="logout"` | `@click="logout"`（element-plus 的 `el-dropdown-item` 转发 click） |
| `SidebarItem.vue:11` | `<el-submenu ... popper-append-to-body>` | `<el-sub-menu>`（**去除 `popper-append-to-body`**） |
| `table/index.vue`（×6） | `<template slot-scope="scope">` | `<template #default="scope">` |
| `table/index.vue` | `{{ scope.row.status \| statusFilter }}` 过滤器 | 改方法调用 `statusFilter(scope.row.status)` |
| `Sidebar/Item.vue` | `h('span', { slot: 'title' })` render 属性 | `h('span', { class: 'menu-title' })` |

> 说明：Vue3 移除 `.native` 修饰符与 `slot="x"` 属性语法，并彻底移除 `filters`；`slot-scope` 改为 `#default`；`el-dropdown-menu` 在 element-plus 用 `#dropdown` 插槽接收子项。以上改完即可消除模板编译/渲染报错。

### 3.3 element-plus 组件改名

- `el-submenu` → **`el-sub-menu`**（`SidebarItem.vue` 开/闭标签）。
- 注意 `el-sub-menu` 不再接受 `popper-append-to-body`，删除该属性（浮层默认行为由 element-plus 接管，dev 走查确认定位）。
- `sidebar.scss` 的 `.el-submenu__title` / `.el-submenu` / `.el-submenu__icon-arrow` CSS 选择器同步改为 `.el-sub-menu__*` 前缀，与组件改名闭环（否则多级菜单视觉回归）。

### 3.4 图标迁移（`el-icon-*` → `@element-plus/icons-vue`）

- **规则**：`<i class="el-icon-xxx">` / `<el-icon-xxx>` → `<el-icon><Xxx /></el-icon>`，并在 `<script>` 中 `import { Xxx } from '@element-plus/icons-vue'`。
- **命名映射**：`el-icon-caret-bottom` → `CaretBottom`、`el-icon-time` → `Time` …… 规则为 **kebab 去 `el-icon-` 前缀、转 PascalCase 首字母大写**（组件名以 `@element-plus/icons-vue` 导出为准）。
- `src/icons/svg` 自定义 SVG 仍走 `vite-plugin-svg-icons`（`<svg-icon>`），**不变**。
- **实际真实渲染图标仅 2 处**：`Navbar.vue` 的 `CaretBottom`、`table/index.vue` 的 `Time`。此外 `router/index.js` 中 `icon: 'el-icon-s-help'` 等为路由 meta 字符串（数据，非 `<i>` 渲染），本阶段不改；`sub-el-icon` 为自定义 CSS 类误报，跳过。

### 3.5 全局 API 清理（可选，非阻断 — 已执行）

- `form/index.vue` 的 `this.$message` → `import { ElMessage } from 'element-plus'` 显式调用（`permission.js` 实测无 `$message`，无需处理）。element-plus 经 `app.use(ElementPlus)` 全局注册后 `this.$message` 仍可用，故**不阻断运行**；本阶段一并清理以保持一致。[决策点 D3]

### 3.6 验证方式

- `npm run dev`（含 mock `/dev-api`）本地起服务，逐视图人工走查（登录 / 表单 / 表格 / 树 / 嵌套菜单 / 404 / 布局 / 下拉菜单）。
- `npm run build:prod` 通过（**本轮实测已通过**：`✓ built in 33.89s`，1715 模块）。
- `npm run lint`：**当前因 Stage 1 残留的 ESLint 10 + `.eslintrc.js` 不兼容而失败**（ESLint v9+ 默认 flat config `eslint.config.js`，`.eslintrc.js` 已不支持）。此问题与 Stage 2 代码无关，列为 Stage 3 的 ESLint flat-config 迁移项，不阻塞本 PR。

- **`el-dropdown` `#dropdown` 插槽写法**：element-plus 用 `<el-dropdown-menu #dropdown>` 或 `<template #dropdown>` 包子项，已编译通过验证。

- **`filters` 移除**：`statusFilter` 改为 `methods` 内 map 调用，已编译通过。
- **`sidebar.scss` 选择器**：`el-submenu`→`el-sub-menu` 必须与组件改名同步，否则多级菜单视觉回归；已同步。
- **全局 `$message`**：已清理为 `ElMessage` 并显式 import，无运行时报错风险。
- **无历史 CI 基线**：合并前必须本地全量验证（§5）。
- 回滚：全部在 `fix/migrate-vue3-stage2` 分支；合并由你 review，不自动合并。
